`MediaQuery` 用于获取当前设备屏幕的各种物理与系统配置参数（如屏幕宽高、设备像素比、状态栏高度、屏幕方向等）。如：

```Dart
// 获取当前屏幕的宽度和高度
double screenWidth = MediaQuery.of(context).size.width;
double screenHeight = MediaQuery.of(context).size.height;
```

### 1. 实际上，MediaQueryData 是它的数据载体

通过 `MediaQuery.of(context)` 返回的是一个 `MediaQueryData` 对象。上面代码中的 `size.width` 实际上是读取了 `MediaQueryData` 内部的属性，它等价于：

```Dart
MediaQueryData mediaQueryData = MediaQuery.of(context);
double screenWidth = mediaQueryData.size.width;
```

在 `MediaQueryData` 中，有三个最容易混淆的**边界边距属性**（通常在处理键盘弹起和刘海屏时需要精准区分）：

- **`padding`**：由操作系统决定的安全区域缩进（如顶部的刘海、底部的 Indicator 条）。
    
- **`viewInsets`**：被系统 UI 完全遮挡的区域。最典型的场景就是**软键盘弹起**时，`viewInsets.bottom` 会变成键盘的高度。
    
- **`viewPadding`**：屏幕四周的系统物理边缘区域（无论软键盘是否弹起，这个值都保持不变）。
    

它们之间的数学等价关系通常为：

$$\text{padding} = \max(\text{viewPadding} - \text{viewInsets}, 0.0)$$

### 2. 核心原理：InheritedWidget 的数据分发

`MediaQuery` 本质上是一个 **`InheritedWidget`**。这意味着它利用了 Flutter 框架自带的“依赖通知机制”。

我们可以看其内部的核心简化实现：

```Dart
class MediaQuery extends InheritedWidget {
  const MediaQuery({
    Key? key,
    required this.data,
    required Widget child,
  }) : super(key: key, child: child);

  final MediaQueryData data;

  // 提供给子组件获取数据的方法
  static MediaQueryData of(BuildContext context) {
    final MediaQuery? query = context.dependOnInheritedWidgetOfExactType<MediaQuery>();
    if (query != null) return query.data;
    throw FlutterError('MediaQuery.of() called with a context that does not contain a MediaQuery.');
  }

  @override
  bool updateShouldNotify(MediaQuery oldWidget) => data != oldWidget;
}
```

当手机发生**横竖屏切换**或者**软键盘弹出**时，底层系统会触发根部的 `MediaQuery` 重新构建，传入新的 `MediaQueryData`。由于 `updateShouldNotify` 返回 `true`，所有调用了 `MediaQuery.of(context)` 的子组件都会被标记为 `dirty` 并自动触发 `build` 刷新。

### 3. 与 RenderObject 的间接关系

不同于 `SizedBox` 或 `Padding` 会直接映射到具体的 `RenderObject`（如 `RenderConstrainedBox` 或 `RenderPadding`），`MediaQuery` **本身并不直接参与复杂的绘制与布局逻辑**。

它作为一个声明在树顶部的 `InheritedWidget`，其主要的 `create` 和更新逻辑发生在一个特殊的组件 —— **`WidgetsApp`**（或 `MaterialApp` / `CupertinoApp`）内部。

在更底层的 `View` 渲染层面，它是这样被包装的：

```Dart
// 在 WidgetsApp 内部的简易逻辑结构
Widget build(BuildContext context) {
  return RootWidget(
    child: _MediaQueryFromView( // 内部会监听来自底层 window 的 metrics 变化
      view: View.of(context),
      child: Builder(
        builder: (BuildContext context) {
          // 最终在这里向下包裹 MediaQuery 
          return MediaQuery(
            data: MediaQueryData.fromView(View.of(context)),
            child: widget.child!,
          );
        },
      ),
    ),
  );
}
```

每当底层的物理视图界面（`FlutterView`）检测到 `onMetricsChanged`（屏幕尺寸、旋转变化）或 `onPlatformBrightnessChanged`（深色模式切换）时，都会触发这个树顶部的 `MediaQuery` 进行重绘，进而影响整个应用。

### 4. 进阶：如何精细化控制局部刷新（Performance Optimization）

因为 `MediaQuery.of(context)` 会让当前的 `context` 依赖整个 `MediaQueryData`。如果我们在页面中只想知道“当前是不是深色模式”，而不想在“键盘弹起（`viewInsets` 改变）”时触发该页面重绘，在 Flutter 3.x 之后，我们可以使用精细化监听：

```Dart
// ❌ 不推荐：键盘弹起或屏幕宽高变化都会导致该 Widget 重新 build
bool isDark = MediaQuery.of(context).platformBrightness == Brightness.dark;

//  推荐：只有在深色/浅色模式切换时，才会触发当前 Widget 重新 build
bool isDarkOpt = MediaQuery.maybePlatformBrightnessOf(context) == Brightness.dark;
```

其底层等价于利用了 `InheritedModel` 的 `aspect`（切片）机制，只锁定 `MediaQueryData` 的某一个特定属性进行依赖追踪：

```Dart
static Brightness platformBrightnessOf(BuildContext context) {
  // 只依赖 platformBrightness 这一单一方面的数据变更
  return InheritedModel.inheritFrom<MediaQuery>(context, aspect: 'platformBrightness')!.data.platformBrightness;
}
```
